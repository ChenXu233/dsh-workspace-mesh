# 取证快照

> **状态**：只读归档
> **日期**：2026-11-01
> **读者**：想知道「这个结论当初凭什么成立」的人
> **口径**：这些文件记录取证过程，不描述当前实现

这些是**证据**，不是现行契约。结论已经折进 `SPEC.md` 或 `docs/reference/`；原文留在这里，是因为复现步骤和证据索引（file:line）以后还要用。

## 1. 使用规则

1. **只读**。新结论不写回这里，而是折进现行文档。
2. 与当前实现不一致时，先分清是「后来改了」还是「当时观察错了」——不默认任何一方为准（[AGENTS.md](../../AGENTS.md) §2）。这里写的是「某天某环境下观察到的」，不主张描述现状。
3. 引用时引小节号（如 `p1-transport.md` §2.2），不要转述成「据文档说」。
4. 新增取证的做法：先在任务里把结论压缩成几句话，折进 `SPEC.md` / `reference/`，再把原文归档到这里。**不要把完整调研报告直接落盘**——一轮调研动辄几十 KB，真正承重的只有几 KB，剩下的会变成没人整合的垃圾。
5. 命名 `<编号>-<主题>.md`；开头写清日期、问题、结论、未验证项。
6. 取证里的机器路径与代码片段保留原样（自检脚本对 `docs/evidence/` 豁免绝对路径规则）；现行文档里不允许出现盘符路径。

## 3. 尚未被引用时的处理

一份取证文档如果三个月没人引用，说明它回答的问题已经不再是问题——删掉。git 里有历史，不需要 `archive/` 目录。
